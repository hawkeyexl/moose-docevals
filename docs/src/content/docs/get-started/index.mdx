Zero to a real finding. No concepts first — those are on the
[next page](/moose-docevals/get-started/how-moose-docevals-works/), and you will understand them faster having
seen a run.

Requires Node.js 24+.

## 1. Install and scaffold

```bash
npm i -D moose-docevals
```

```bash
npx moose-docevals init
```

`init` writes a starter `moose.config.yaml`: a `files.include` glob, a pinned judge model, and a
few named evals to start from — including `no-future-promises` and `fresh-enough`.

## 2. Get a finding without spending anything

Before touching frontmatter or a provider, run the deterministic graders over your docs:

```bash
npx moose-docevals run --deterministic-only
```

`--deterministic-only` skips the LLM judge entirely, so this needs no API key and costs nothing. On
a corpus that has never been checked, `fresh-enough` alone usually finds something.

```console
$ npx moose-docevals run test/fixtures/pages/docs/actions/goTo.mdx --deterministic-only --no-generate
test/fixtures/pages/docs/actions/goTo.mdx
  skip no-future-promises
       judge skipped (--deterministic-only)
  FAIL fresh-enough
       error:4 [freshness/stale] Page last reviewed 937 days ago (max 365)
  pass readable
  pass frontmatter-valid

Suites
  reference: 2/3 passed — 67% vs target 100% below target (1 skipped)
```

Read the finding line as `severity:line [ruleId] message`. The exit code is `1` — a finding, not an
error. [Exit codes](/moose-docevals/reference/output-and-exit-codes/) explains why that distinction
matters.

## 3. Declare your own eval

Add an `evals` key to a page's frontmatter. The array form is the minimum:

```yaml
---
title: Installation
last-reviewed: 2026-06-01
evals:
  - no-future-promises
  - name: install-command-present
    assertion: The page contains a bash code block with `npm i -g doc-detective`.
    grader: command
---
```

Two entries, two different things. `no-future-promises` **references** a named eval from your
config. The second **defines** one inline — and being `command`-graded with an assertion but no
command, moose-docevals will write the check script for it.

Check what resolved before running anything:

```bash
npx moose-docevals list docs/installation.mdx
```

## 4. Add the judge

Set your key and drop `--deterministic-only`:

```bash
export ANTHROPIC_API_KEY=sk-…
npx moose-docevals run docs/installation.mdx
```

Each llm eval runs three times independently; agreement decides the verdict, and anything the judge
is unsure about routes to [human review](/moose-docevals/judge/human-review/) rather than guessing.

No API key, or a security review to satisfy? The `claude-cli` provider uses local CLI auth and needs
no key, and the `openai` provider takes any OpenAI-compatible `baseUrl` including a self-hosted one.
See [Choose a provider](/moose-docevals/judge/choose-a-provider/).

## 5. Gate a pull request

```yaml
- name: moose-docevals
  run: npx moose-docevals run --format github
  env:
    ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
```

`--format github` annotates the offending lines inline in the diff. Full recipes, the exit-code
contract, and the fork-safety rules are in [Run it in CI](/moose-docevals/ci/).
