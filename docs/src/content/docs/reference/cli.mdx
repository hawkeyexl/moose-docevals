Eight commands. Every flag below is verified against `src/cli.ts`; the exit codes are exercised by
the inline tests at the foot of this page.

## Common conventions

Commands that operate on pages take **positional globs**. With none given, the config's
`files.include` applies.

| Flag | Commands | Meaning |
|---|---|---|
| `-c, --config <path>` | all except `init` | Path to `moose.config.yaml`. Without it, moose-docevals looks for that filename in the working directory; with no file at all, built-in defaults apply and there are no named evals or suites. |
| `-f, --format <format>` | `list`, `run`, `fill` | Output format. `run` accepts `human`, `json`, `markdown`, `github`, `sarif`, `junit`, `html`; `list` and `fill` accept `human` and `json`. Anything else — including `run`'s `markdown` passed to `list` — is a usage error: **exit 2**, allowed set in the message. See [Output and exit codes](/moose-docevals/reference/output-and-exit-codes/#which-formats-each-command-accepts). |
| `--provider <name>` | `run`, `generate`, `fill`, `promote`, `calibrate` | `anthropic`, `openai`, `claude-cli`, or `llama-cpp`. Overrides `provider.default`. |
| `--model <model>` | same as above | Overrides the model for the selected provider. |

Flags override config; they do not bypass it. An unset flag falls through to the resolved config
value, so a config file and the CLI reach the same code paths.

## `moose-docevals run [globs...]`

Runs every resolved eval: deterministic graders first (cheapest first), then the AI judge, then
human-review resolution.

| Flag | Effect |
|---|---|
| `--deterministic-only` | Run only `command` and `tool:*` graders. AI-graded evals report as `skipped`. No provider needed — this is the offline path. |
| `--ai-only` | Run only AI-judged evals; skip deterministic graders. |
| `--eval <name>` | Run only this eval. Repeat the flag for more than one (`--eval a --eval b`) — names are **not** space-separated, because a variadic flag would swallow the following glob. **Suite targets are not evaluated while a filter is active** — see below. A name that matches nothing is a usage error: **exit 2**. |
| `--suite <name>` | Run only the evals the named suite lists. Same suspension of suite targets; a suite the config does not define is **exit 2**, with the defined names in the message. |
| `--since <ref>` | Evaluate only the pages that differ between `<ref>` and `HEAD`. Corpus-wide graders still see every page. Suite targets are suspended, as with `--eval`. Nothing changed is **exit 0**, not an error — see below. |
| `--allow-execution <kind...>` | Grant content-authored execution for this run: `frontmatter-commands`, `page-embedded-steps`, or both. Adds to `execution.allow`; repeatable. |
| `--no-execution` | Clear every execution grant for this run, whatever the config says. |
| `--no-generate` | Do not generate scripts for command evals that lack a `command`. |
| `--no-cache` | Bypass the judge response cache. |
| `--fail-on-review` | Exit 1 when any eval lands in the human-review zone. |
| `--runs <n>` | Ensemble runs per eval. Overrides `judge.ensemble-runs` (default 3), and an eval's own `runs`. |
| `--chunk-chars <n>` | Characters of page per judge call. A longer page is read in parts and judged once against the collected evidence. Overrides `judge.chunk-chars` (default 12000). |
| `--max-turns <n>` | Stop judging after this many uncached **ensemble runs**. One ai eval spends `judge.ensemble-runs` turns; a cached ensemble spends none. A run may make a second provider call when the first response fails schema validation, so this is a floor on API calls rather than an exact count. Overrides `judge.max-turns` (default: unbounded). |
| `--baseline [path]` | Fail only on findings a recorded baseline does not already hold. With no path, the configured `baseline:`, then `.moose-docevals-baseline.json`. |
| `--no-baseline` | Ignore the configured `baseline:` for this run, so the full backlog reports again. |
| `--write-baseline [path]` | Record this run's findings as the baseline. **With no path, the configured one** — see below. |

### The findings baseline

A baseline records today's findings so a run fails only on new ones. It covers **findings**, which
means `command` and `tool:*` graders — not judged verdicts, not an eval that errored, not a suite
target. Full behavior in [Retrofit a legacy
corpus](/moose-docevals/adopt/retrofit-a-legacy-corpus/#the-ratchet); the file itself in
[Files and state](/moose-docevals/reference/files-and-state/#findings-baseline).

**A bare `--write-baseline` records into the configured path, not the default.** Get that backwards
and a repo pointing `baseline:` somewhere custom records into a file nothing reads — every run still
fails, an unreferenced file grows in the diff, and the ratchet does nothing while looking like it
works. Recording with no `baseline:` set at all is reported as a warning naming the config file.

A recording run applies the baseline it just wrote, so it exits `0` on findings: recording a finding
is declaring it accepted, and a `--write-baseline` you have to wrap in `|| true` loses the exit code
that matters on the next run. A suite below target or an errored eval still exits `1`.

Every re-record reports the diff against the previous file:

```console
Baseline .moose-docevals-baseline.json: recorded 1 finding(s) (+0, -1).
  1 previously recorded finding(s) are no longer in the baseline. If this run covered less of the
  corpus than the last one, they have just been forgiven.
```

`removed` is the number to watch — it is the only thing in a CI log that makes an over-forgiving
re-record visible. A baseline whose JSON, `version`, or fingerprints are malformed is **exit 2**,
with the offending entry named.

### Selecting evals suspends suite enforcement

`--eval` and `--suite` narrow the run after resolution and before grading. Resolution still happens
in full, so a bad `eval-*` key or an unknown grader on a page you filtered out still reports.

A suite target is a claim about a body of checks. A run narrowed to one passing eval out of a suite
of twelve would compute `1/1 = 100%`, clear a target of `1.0`, and exit `0` having checked almost
nothing — so **while either flag is active, suite targets are reported but not enforced**. Each
summary carries the numbers it measured and withholds the verdict:

```console
$ moose-docevals run --deterministic-only --no-generate --eval readable
...
Suites
  how-to: 2/2 passed — 100% vs target 100% partial — filtered run, target not evaluated
  reference: 4/4 passed — 100% vs target 100% partial — filtered run, target not evaluated
```

What still holds:

- A `fail` or an `error` among the evals that ran exits **1**.
- An `error`-level resolution problem exits **1**.
- A filter matching no evals exits **2**. A green run over zero evals is never the answer.
- `--suite` filters, it does not redefine. It selects the evals the named suite lists, wherever
  those evals resolve; each result still reports under the suite its own page resolved to, and
  `target-pass-rate` is untouched.

This is why `--eval` is a local debugging flag and not a CI invocation — see
[Exit codes and annotations](/moose-docevals/ci/exit-codes-and-annotations/#a-filtered-run-is-not-a-gate)
and the `partial` field in
[Output and exit codes](/moose-docevals/reference/output-and-exit-codes/#suites).

### Scoping a run to what changed

`--since <ref>` grades only the pages that differ between `<ref>` and `HEAD`, so a job on a pull
request does not re-judge a corpus nobody touched.

```console
$ moose-docevals run --since origin/main --format github
```

The comparison is `<ref>...HEAD` — three dots, so the diff is against the merge base. That is what a
pull request means by "changed": commits that landed on the base branch after yours forked are not
your changes. It also means **uncommitted working-tree edits are not included**, which is right for
CI and surprising locally. Edit a page, run `--since main`, and that page is not graded until the
edit is committed.

Two things the scope does **not** narrow:

- **Corpus-wide graders.** `tool:differentiation` compares related pages against each other, so its
  input set *is* its subject. Hand it one page and it has nothing to compare against, reports no
  findings, and the eval records a **pass** — scoping it would delete the check rather than shrink
  it. Corpus graders therefore keep the whole corpus. The visible consequence: a scoped run can
  report a finding on a page you did not touch. The message names the other page.
- **Resolution.** Every page is still read and resolved, so a bad `eval-*` key or an unknown grader
  on a page outside the scope still reports, and still exits `1`.

Three things it does change:

- **Nothing changed is exit `0`**, the opposite of an `--eval` that matches nothing. A branch that
  touched only source is a correct answer, not a typo. The run says so rather than going quiet:

  ```console
  No pages changed since origin/main — nothing was evaluated.
  ```

- **Suite targets are reported but not enforced**, exactly as under `--eval`. A scoped run measured
  a sample of the corpus, so it withholds the verdict.
- **`--write-baseline` is refused**: **exit 2**, before git is even run. A re-record rebuilds the
  file from this run's findings, so recording from a scoped run would forgive every finding the
  scope excluded. Reading a baseline is unaffected, and pages outside the scope are not reported as
  no longer occurring.

In GitHub Actions, `actions/checkout` clones with `fetch-depth: 1`, so `origin/main` is usually not
present locally and `--since origin/main` is **exit 2** with a message naming the ref. Fetch the
full history:

```yaml
- uses: actions/checkout@v7
  with:
    fetch-depth: 0
```

`--since` has no config key, for the same reason `--eval` and `--suite` have none: it selects work
for one invocation rather than setting policy, and the ref you compare against belongs to the job,
not to the repository. `list` takes no `--since`.

`--since` and the [judge cache](/moose-docevals/ci/cost-and-caching/) are complements. `--since`
avoids dispatching work on a page that did not change; the cache avoids paying twice for a page that
did change but whose prompt did not.

## `moose-docevals list [globs...]`

Shows the resolved eval plan per page and runs nothing. This is the dry run for
[named evals and suites](/moose-docevals/evals/named-evals-and-suites/) — use it when a page's frontmatter,
a referenced eval, and a suite could each contribute the same name.

```console
$ moose-docevals list test/fixtures/pages/docs/actions/goTo.mdx
test/fixtures/pages/docs/actions/goTo.mdx (suite: reference)
  - no-future-promises [ai, regression, config]
  - fresh-enough [tool:freshness, regression, config]
  - readable [tool:reading-level, regression, config]
  - frontmatter-valid [tool:docmeta, regression, config]

1 pages, 4 evals resolved
```

Each line is `name [grader, type, source]`, where source is `config` or `page`.

| Flag | Effect |
|---|---|
| `--eval <name>` | Show only this eval. Repeatable, like the `run` flag. |
| `--suite <name>` | Show only the evals the named suite lists. |

These are the same two filters `run` takes, and they fail the same way: a name that matches nothing
is **exit 2**. Reach for them to answer "what would `--eval X` actually have run" without spending a
grading pass.

## `moose-docevals generate [globs...]`

Writes a check script for every `command` eval that has a plain-language assertion but no `command`,
then records the command in frontmatter. See
[Deterministic checks](/moose-docevals/evals/deterministic-checks/).

Exits 1 if any target failed to generate.

## `moose-docevals fill [globs...]`

Proposes evals for each page from its content, gated on a self-reported confidence.

| Flag | Effect |
|---|---|
| `--dry-run` | Report proposals without writing frontmatter. Run this first — you see every proposal, and how many inference calls the pass made, before anything touches the repo. |
| `--confidence <n>` | Minimum confidence to write, 0–1. Overrides `fill.confidence-threshold` (default `0.7`). Values above 1 are a usage error. |
| `--max-turns <n>` | Stop after this many uncached inference calls — exactly one per page filled. Overrides `fill.max-turns` (default: unbounded). |
| `--no-cache` | Bypass the proposal cache. |

Raw proposals are cached **before** the confidence gate, so re-running at a different `--confidence`
spends no turns.

## `moose-docevals promote [globs...]`

Reviews ai-graded evals and reports which are expressible as deterministic checks. **Report-only by
default**; `--write` applies the conversions. See
[Promote to deterministic](/moose-docevals/adopt/promote-to-deterministic/).

## `moose-docevals calibrate`

Measures judge agreement against a human-verified golden set.

| Flag | Effect |
|---|---|
| `--golden <dir>` | Golden set directory. Default `.moose-docevals/golden`. |
| `--seed` | Write golden candidates from recorded reviews into `<golden>/from-reviews.yaml`, then exit. Judges nothing and constructs no provider, so it runs with no API key. Idempotent on `(file, eval)`: re-running updates rather than duplicates, and never un-reviews a confirmed case. Every new case lands `reviewed: false`. |
| `--runs <n>` | Ensemble runs per case. |
| `--max-turns <n>` | Stop judging after this many uncached **ensemble runs** — the same unit as `run`, since calibration goes through the same judge. One case spends `judge.ensemble-runs` turns. Run-wide, not per case: every case is judged in one batched call. A cached case spends none. |
| `--no-cache` | Bypass the judge response cache. |

Exits 1 when agreement is below the threshold. Unreviewed and stale cases are judged and **counted**
toward that rate, flagged `[unreviewed]` / `[stale]` per case with a summary line naming the counts.
See [Calibrate](/moose-docevals/judge/calibrate/).

## `moose-docevals init`

Writes a starter `moose.config.yaml` in the working directory. Takes no options.

## `moose-docevals review [file] [eval] [verdict]`

With no arguments, lists the evals awaiting a human verdict. With all three, records one.

| Flag | Effect |
|---|---|
| `--reviewer <name>` | Reviewer recorded with the verdict. |
| `--note <text>` | Optional note. |

`verdict` is `pass` or `fail`. Supplying a file without an eval and verdict is a usage error. See
[Human review](/moose-docevals/judge/human-review/).

## Exit codes

| Code | Meaning |
|---|---|
| `0` | Everything passed. |
| `1` | Findings, errors, or a suite below its target pass rate. The author's problem. |
| `2` | Operational or usage error — bad config, missing provider, malformed flag. Not the author's problem. |

Full detail in [Output and exit codes](/moose-docevals/reference/output-and-exit-codes/).
