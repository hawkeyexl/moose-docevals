Eight commands. Every flag below is verified against `src/cli.ts`; the exit codes are exercised by
the inline tests at the foot of this page.

## Common conventions

Commands that operate on pages take **positional globs**. With none given, the config's
`files.include` applies.

| Flag | Commands | Meaning |
|---|---|---|
| `-c, --config <path>` | all except `init` | Path to `moose.config.yaml`. Without it, moose-docevals looks for that filename in the working directory; with no file at all, built-in defaults apply and there are no named evals or suites. |
| `-f, --format <format>` | `list`, `run`, `fill` | Output format. `run` accepts `human`, `json`, `markdown`, `github`, `sarif`, `junit`; `list` and `fill` accept `human` and `json`. Anything else — including `run`'s `markdown` passed to `list` — is a usage error: **exit 2**, allowed set in the message. See [Output and exit codes](/moose-docevals/reference/output-and-exit-codes/#which-formats-each-command-accepts). |
| `--provider <name>` | `run`, `generate`, `fill`, `promote`, `calibrate` | `anthropic`, `openai`, or `claude-cli`. Overrides `provider.default`. |
| `--model <model>` | same as above | Overrides the model for the selected provider. |

Flags override config; they do not bypass it. An unset flag falls through to the resolved config
value, so a config file and the CLI reach the same code paths.

## `moose-docevals run [globs...]`

Runs every resolved eval: deterministic graders first (cheapest first), then the AI judge, then
human-review resolution.

| Flag | Effect |
|---|---|
| `--deterministic-only` | Run only `command` and `tool:*` graders. AI-graded evals report as `skipped`. No provider needed — this is the offline path. |
| `--ai-only` | Run only AI-judged evals; skip deterministic graders. |
| `--eval <name...>` | Run only the evals with these names, space-separated. **Suite targets are not evaluated while a filter is active** — see below. A name that matches nothing is a usage error: **exit 2**. |
| `--suite <name>` | Run only the evals the named suite lists. Same suspension of suite targets; a suite the config does not define is **exit 2**, with the defined names in the message. |
| `--no-frontmatter-commands` | Skip `command` evals declared in **page frontmatter**. See [Untrusted pull requests](/moose-docevals/ci/untrusted-pull-requests/) — this does **not** gate `tool:doc-detective`. |
| `--no-generate` | Do not generate scripts for command evals that lack a `command`. |
| `--no-cache` | Bypass the judge response cache. |
| `--fail-on-review` | Exit 1 when any eval lands in the human-review zone. |
| `--runs <n>` | Ensemble runs per eval. Overrides `judge.ensemble-runs` (default 3). |
| `--max-turns <n>` | Stop judging after this many uncached inference calls. Counts calls, not pages: one ai eval spends `judge.ensemble-runs` turns, and a cached ensemble spends none. Overrides `judge.max-turns` (default: unbounded). |

### Selecting evals suspends suite enforcement

`--eval` and `--suite` narrow the run after resolution and before grading. Resolution still happens
in full, so a bad `eval-*` key or an unknown grader on a page you filtered out still reports.

A suite target is a claim about a body of checks. A run narrowed to one passing eval out of a suite
of twelve would compute `1/1 = 100%`, clear a target of `1.0`, and exit `0` having checked almost
nothing — so **while either flag is active, suite targets are reported but not enforced**. Each
summary carries the numbers it measured and withholds the verdict:

```console
$ moose-docevals run --deterministic-only --no-generate --eval readable
...
Suites
  how-to: 2/2 passed — 100% vs target 100% partial — filtered run, target not evaluated
  reference: 4/4 passed — 100% vs target 100% partial — filtered run, target not evaluated
```

What still holds:

- A `fail` or an `error` among the evals that ran exits **1**.
- An `error`-level resolution problem exits **1**.
- A filter matching no evals exits **2**. A green run over zero evals is never the answer.
- `--suite` filters, it does not redefine. It selects the evals the named suite lists, wherever
  those evals resolve; each result still reports under the suite its own page resolved to, and
  `target-pass-rate` is untouched.

This is why `--eval` is a local debugging flag and not a CI invocation — see
[Exit codes and annotations](/moose-docevals/ci/exit-codes-and-annotations/#a-filtered-run-is-not-a-gate)
and the `partial` field in
[Output and exit codes](/moose-docevals/reference/output-and-exit-codes/#suites).

## `moose-docevals list [globs...]`

Shows the resolved eval plan per page and runs nothing. This is the dry run for
[named evals and suites](/moose-docevals/evals/named-evals-and-suites/) — use it when a page's frontmatter,
a referenced eval, and a suite could each contribute the same name.

```console
$ moose-docevals list test/fixtures/pages/docs/actions/goTo.mdx
test/fixtures/pages/docs/actions/goTo.mdx (suite: reference)
  - no-future-promises [ai, regression, config]
  - fresh-enough [tool:freshness, regression, config]
  - readable [tool:reading-level, regression, config]
  - frontmatter-valid [tool:docmeta, regression, config]

1 pages, 4 evals resolved
```

Each line is `name [grader, type, source]`, where source is `config` or `page`.

| Flag | Effect |
|---|---|
| `--eval <name...>` | Show only the evals with these names. |
| `--suite <name>` | Show only the evals the named suite lists. |

These are the same two filters `run` takes, and they fail the same way: a name that matches nothing
is **exit 2**. Reach for them to answer "what would `--eval X` actually have run" without spending a
grading pass.

## `moose-docevals generate [globs...]`

Writes a check script for every `command` eval that has a plain-language assertion but no `command`,
then records the command in frontmatter. See
[Deterministic checks](/moose-docevals/evals/deterministic-checks/).

Exits 1 if any target failed to generate.

## `moose-docevals fill [globs...]`

Proposes evals for each page from its content, gated on a self-reported confidence.

| Flag | Effect |
|---|---|
| `--dry-run` | Report proposals without writing frontmatter. Run this first — you see every proposal, and how many inference calls the pass made, before anything touches the repo. |
| `--confidence <n>` | Minimum confidence to write, 0–1. Overrides `fill.confidence-threshold` (default `0.7`). Values above 1 are a usage error. |
| `--max-turns <n>` | Stop after this many uncached inference calls — one per page filled. Overrides `fill.max-turns` (default: unbounded). |
| `--no-cache` | Bypass the proposal cache. |

Raw proposals are cached **before** the confidence gate, so re-running at a different `--confidence`
spends no turns.

## `moose-docevals promote [globs...]`

Reviews ai-graded evals and reports which are expressible as deterministic checks. **Report-only by
default**; `--write` applies the conversions. See
[Promote to deterministic](/moose-docevals/adopt/promote-to-deterministic/).

## `moose-docevals calibrate`

Measures judge agreement against a human-verified golden set.

| Flag | Effect |
|---|---|
| `--golden <dir>` | Golden set directory. Default `.moose-docevals/golden`. |
| `--seed` | Write golden candidates from recorded reviews into `<golden>/from-reviews.yaml`, then exit. Judges nothing and constructs no provider, so it runs with no API key. Idempotent on `(file, eval)`: re-running updates rather than duplicates, and never un-reviews a confirmed case. Every new case lands `reviewed: false`. |
| `--runs <n>` | Ensemble runs per case. |
| `--max-turns <n>` | Stop judging after this many uncached inference calls. Run-wide, not per case — every case is judged in one batched call. A cached case spends none. |
| `--no-cache` | Bypass the judge response cache. |

Exits 1 when agreement is below the threshold. Unreviewed and stale cases are judged and **counted**
toward that rate, flagged `[unreviewed]` / `[stale]` per case with a summary line naming the counts.
See [Calibrate](/moose-docevals/judge/calibrate/).

## `moose-docevals init`

Writes a starter `moose.config.yaml` in the working directory. Takes no options.

## `moose-docevals review [file] [eval] [verdict]`

With no arguments, lists the evals awaiting a human verdict. With all three, records one.

| Flag | Effect |
|---|---|
| `--reviewer <name>` | Reviewer recorded with the verdict. |
| `--note <text>` | Optional note. |

`verdict` is `pass` or `fail`. Supplying a file without an eval and verdict is a usage error. See
[Human review](/moose-docevals/judge/human-review/).

## Exit codes

| Code | Meaning |
|---|---|
| `0` | Everything passed. |
| `1` | Findings, errors, or a suite below its target pass rate. The author's problem. |
| `2` | Operational or usage error — bad config, missing provider, malformed flag. Not the author's problem. |

Full detail in [Output and exit codes](/moose-docevals/reference/output-and-exit-codes/).
