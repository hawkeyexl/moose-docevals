## The `docevals` namespace

`moose.config.yaml` is shared by every tool in the moose family. Each tool reads one top-level key,
so **every setting on this page lives under `docevals:`**:

```yaml
docevals:
  version: 1
  judge:
    ensembleRuns: 3
```

The key names in the tables below are written relative to that namespace: `files.include` means
`docevals.files.include` in the file.

Root keys moose-docevals does not recognize belong to sibling tools and are ignored, so another
tool's settings can sit beside yours in the same file. Inside `docevals:`, unknown keys are rejected
at every level — a typo there is a startup error rather than a silently ignored setting.

One consequence is worth knowing: because the root is permissive, misspelling the namespace itself
(`docevlas:`) is not an error. moose-docevals reads it as another tool's config and runs on pure
defaults — no named evals, no suites, and a passing exit code. `moose-docevals init` writes the key
correctly; if a run reports far fewer evals than you expect, check that spelling first.

With no config file present, every default below applies and there are no named evals or suites. A
file left over from before the rename — `docevals.config.yaml` — is not read; moose-docevals stops
and tells you to migrate rather than silently running on defaults.

## `version`

Required. Must be `1`.

## `files`

| Key | Type | Default |
|---|---|---|
| `files.include` | string[] | `["**/*.{md,mdx}"]` |
| `files.exclude` | string[] | `["**/node_modules/**"]` |

Positional globs on the CLI override `files.include` for that run.

## `defaults`

| Key | Type | Default | Notes |
|---|---|---|---|
| `defaults.suite` | string \| null | `null` | Suite applied to pages that name none. Must be a defined suite or startup fails. |
| `defaults.failFast` | boolean | `false` | |
| `defaults.concurrency` | integer ≥ 1 | `4` | Bounded concurrency across targets. |

## `judge`

| Key | Type | Default | Notes |
|---|---|---|---|
| `judge.ensembleRuns` | integer ≥ 1 | `3` | Independent runs aggregated by consensus. |
| `judge.temperature` | number ≥ 0 | `0` | |
| `judge.zones.autoPass` | number 0–1 | `0.8` | Confidence at or above which a passing consensus auto-passes. |
| `judge.zones.autoFail` | number 0–1 | `0.8` | Confidence at or above which a failing consensus auto-fails. |
| `judge.falsePositiveAlert` | number 0–1 | `0.15` | Calibration alerts above this false-positive rate. |
| `judge.cacheDir` | string | `.moose-docevals/cache` | |
| `judge.maxCostUsd` | number \| null | `null` | Hard ceiling that aborts, not a warning. |

Anything between the two zone thresholds lands in human review. See
[How judging works](/moose-docevals/judge/).

## `scripts`

| Key | Type | Default | Notes |
|---|---|---|---|
| `scripts.dir` | string | `{docDir}/moose-docevals` | Where generated scripts go. `{docDir}` expands to the page's directory. |
| `scripts.configDir` | string | `moose-docevals-scripts` | Used when `scripts.dir` has no `{docDir}`; resolved relative to the config file. |
| `scripts.allowFrontmatterCommands` | boolean | `true` | Gates `command` evals declared in page frontmatter. |
| `scripts.timeoutMs` | integer ≥ 1 | `30000` | |

:::caution
`scripts.allowFrontmatterCommands` gates **frontmatter-declared commands only**. The
`tool:doc-detective` grader executes steps embedded in page bodies and is not covered by it. See
[Untrusted pull requests](/moose-docevals/ci/untrusted-pull-requests/).
:::

## `evals`

A map of eval name to definition. Names match `^[a-z0-9][a-z0-9-]*$`.

Every field an eval can carry is documented in
[Frontmatter reference](/moose-docevals/reference/frontmatter/) — the same shape applies whether the eval
is defined here or inline on a page.

```yaml
docevals:
  evals:
    no-future-promises:
      type: regression
      assertion: The page makes no claims about unreleased or future functionality.
      grader: llm
      evidence: All prose sections
      examples:
        pass: Describes only shipped behavior.
        fail: Says "coming soon" or references an unreleased version.
```

## `suites`

A map of suite name to definition.

| Key | Type | Default |
|---|---|---|
| `targetPassRate` | number 0–1 | `1.0` |
| `evals` | string[] | `[]` |

```yaml
docevals:
  suites:
    reference:
      targetPassRate: 1.0
      evals: [no-future-promises, fresh-enough, readable, frontmatter-valid]
    tutorial:
      targetPassRate: 0.7
      evals: [explains-why-before-how, no-future-promises]
```

## Referential integrity

Two checks run at load time and fail the process with exit 2 rather than surfacing later as a
confusing per-page problem:

- A suite may only reference evals defined under `evals`.
- `defaults.suite` must name a defined suite.
