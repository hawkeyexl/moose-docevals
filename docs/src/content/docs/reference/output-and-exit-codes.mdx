description: The human, json, markdown, and github report shapes, and what each exit code means.

Verified against `src/reporters/` and `src/types.ts`, with samples captured from real runs against
the fixture corpus.

## Exit codes

| Code | Meaning | Who acts |
|---|---|---|
| `0` | Everything passed. | Nobody. |
| `1` | Failures, errors, or a suite below its target pass rate. | The page author. |
| `2` | Operational or usage error — bad config, missing provider, malformed flag. | Whoever owns the pipeline. |

**`1` and `2` route to different people**, which is the whole reason they are distinct. A CI recipe
that treats any non-zero exit as "the docs are bad" blames authors for infrastructure problems and
earns the check a reputation for flakiness it does not deserve.

`--fail-on-review` additionally makes exit 1 cover evals sitting in the human-review zone.

## Which formats each command accepts

`-f/--format` is not one shared set. `run` has four reporters; `list` and `fill` render only two.

| Command | Accepted formats |
|---|---|
| `run` | `human`, `json`, `markdown`, `github` |
| `list` | `human`, `json` |
| `fill` | `human`, `json` |

Anything else is a **usage error: exit 2**, with the allowed set in the message. Matching is exact —
`JSON` and `Json` are rejected rather than folded, so a typo surfaces instead of being guessed at.
Passing `run`'s `markdown` to `list` is rejected for the same reason.

```console
$ moose-docevals list docs/ --format xml
moose-docevals: --format must be one of human | json, got "xml"
$ echo $?
2
```

That matters most in CI, where `--format json` is piped into a parser. Exit 2 stops the pipeline;
silently falling back to the human report would hand `jq` ANSI colour codes and still exit 0.

## `--format human`

The default. Per page, one line per eval; then per-suite aggregates.

```console
$ moose-docevals run test/fixtures/pages/docs/actions/goTo.mdx --deterministic-only --no-generate
test/fixtures/pages/docs/actions/goTo.mdx
  skip no-future-promises
       judge skipped (--deterministic-only)
  FAIL fresh-enough
       error:4 [freshness/stale] Page last reviewed 937 days ago (max 365)
  pass readable
  pass frontmatter-valid

Suites
  reference: 2/3 passed — 67% vs target 100% below target (1 skipped)
```

The finding line is `severity:line [ruleId] message`. Colour is applied only on a TTY.

Note the suite line: the skipped eval is excluded from the denominator, so the rate is 2/3 rather
than 2/4.

## `--format json`

One object, for programmatic consumers.

```json
{
  "pages": 1,
  "evalResults": [
    {
      "evalName": "fresh-enough",
      "type": "regression",
      "grader": "tool:freshness",
      "file": "test/fixtures/pages/docs/actions/goTo.mdx",
      "outcome": "fail",
      "findings": [
        {
          "evalName": "fresh-enough",
          "file": "test/fixtures/pages/docs/actions/goTo.mdx",
          "ruleId": "freshness/stale",
          "message": "Page last reviewed 937 days ago (max 365)",
          "severity": "error",
          "line": 4
        }
      ],
      "durationMs": 0
    }
  ],
  "suites": [
    {
      "suite": "reference",
      "total": 4,
      "passed": 2,
      "failed": 1,
      "needsReview": 0,
      "skipped": 1,
      "errored": 0,
      "passRate": 0.6666666666666666,
      "targetPassRate": 1,
      "meetsTarget": false
    }
  ],
  "cost": { "totalUsd": 0, "totalTokens": 0, "cachedEvals": 0, "judgedEvals": 0 },
  "generated": [],
  "exitCode": 1
}
```

### `evalResults[]`

| Field | Notes |
|---|---|
| `outcome` | `pass`, `fail`, `needs-review`, `skipped`, or `error`. |
| `consensus` | Present for llm-graded evals only. |
| `findings` | Present for command/tool evals that produced findings. |
| `generated` | True when this run generated the eval's check script. |
| `via` | `"human-review"` when a persisted review resolved the outcome. |
| `skipReason`, `costUsd`, `durationMs` | |

### `suites[]`

`passRate` is `passed / (total - skipped)`, and `1` when nothing ran. `meetsTarget` compares it to
the suite's `targetPassRate`.

## `--format markdown`

The suite table plus per-page findings, suitable for a PR comment or a job summary.

## `--format github`

Workflow commands for inline annotations, followed by the markdown summary — so the same output
both annotates the diff and works as `$GITHUB_STEP_SUMMARY`.

```text
::error file=test/fixtures/pages/docs/actions/goTo.mdx,line=4,title=moose-docevals%3A fresh-enough::Page last reviewed 937 days ago (max 365)

## moose-docevals results

| Suite | Passed | Failed | Review | Pass rate | Target | |
|---|---|---|---|---|---|---|
| reference | 2 | 1 | 0 | 67% | 100% | ❌ |
```

Severity maps to the annotation level: `error` → `::error`, `warning` → `::warning`, `info` →
`::notice`. Values are escaped per GitHub's rules — `%`, CR, and LF in data; additionally `:` and
`,` in properties, which is why the title reads `moose-docevals%3A`.

A failing **llm** eval annotates the file with the mean confidence and the judge's reasoning, since
it has no line to point at:

```text
::error file=...,title=moose-docevals%3A no-future-promises::LLM judge: fail (confidence 0.93). <reasoning>
```
